# Incident Radar

Консольная утилита на Go для анализа NGINX-логов.

## Чтение источников

Нужен Go 1.26.6 или новее в ветке 1.26. Соберите приложение командой `make build`.

```sh
bin/incident-radar -p sample_logs/access.txt -o report.json
bin/incident-radar --path 'sample_logs/*.txt' --format markdown --output report.md
# В другом терминале запустите make serve
bin/incident-radar -p http://127.0.0.1:8000/mixed.txt -o mixed.json
```

Укажите файл `.log` или `.txt`, glob в кавычках либо HTTP(S) URL. Для glob программа читает все подходящие файлы по очереди в порядке имён. Формат по умолчанию — `json` (`.json`), второй вариант — `markdown` (`.md`). Путь отчёта обязателен, каталог должен существовать, а имя файла — быть свободным.

Параметры `--from` и `--to` принимают даты вида `2025-03-01`. При указании обеих границ начало должно быть раньше конца. Программа пропускает пустые строки. Для каждой повреждённой строки она выводит в stderr `WARN: skipped malformed log line` и продолжает чтение. После чтения всех источников программа сохраняет отчёт по указанному пути.

Проверки проекта запускаются командами `make check` и `make test`.

## Как считается статистика

Границы включают календарный день целиком в часовом поясе самой записи. Каждую границу можно опустить. В расчёт попадают только корректные записи за выбранный период.

Ресурсы сортируются по убыванию числа запросов, при равенстве — по возрастанию строки пути (порядок строк Go). В отчёт входят первые десять. Коды ответов перечисляются по возрастанию.

Среднее число байт округляется до сотых. Для p95 используем nearest-rank: сортируем размеры ответов и берём элемент с номером `ceil(0.95 × N)`, считая с единицы. Для пустой выборки среднее, максимум и p95 равны нулю. В памяти остаются счётчики и один размер на запрос для точного p95.

## Пример отчёта

В [sample_logs/mixed.txt](sample_logs/mixed.txt) две записи и одна повреждённая строка:

```text
192.0.2.1 - - [01/Mar/2025:10:00:00 +0000] "GET /before-error HTTP/1.1" 200 100 "-" "curl/8.0"
this line is intentionally malformed
192.0.2.2 - - [01/Mar/2025:10:01:00 +0000] "GET /after-error HTTP/1.1" 500 500 "-" "curl/8.0"
```

```sh
bin/incident-radar -p sample_logs/mixed.txt -o mixed.json
bin/incident-radar -p sample_logs/mixed.txt -f markdown -o mixed.md
```

Оба запуска выводят одно предупреждение. Содержимое `mixed.json`:

```json
{
  "files": ["sample_logs/mixed.txt"],
  "totalRequestsCount": 2,
  "responseSizeInBytes": {"average": 300, "max": 500, "p95": 500},
  "resources": [
    {"resource": "/after-error", "count": 1},
    {"resource": "/before-error", "count": 1}
  ],
  "responseCodes": [
    {"code": 200, "count": 1},
    {"code": 500, "count": 1}
  ]
}
```

Markdown содержит те же данные. Например, в разделе «Коды ответа» будут строки:

| Код | Запросы |
| --- | ---: |
| 200 OK | 1 |
| 500 Internal Server Error | 1 |

## Коды завершения

| Код | Значение |
| ---: | --- |
| 0 | Отчёт сохранён. Отдельные повреждённые строки пропущены. |
| 1 | Внутренняя ошибка, например сбой записи отчёта. |
| 2 | Ошибка аргументов, недоступный источник или неверный путь отчёта, включая уже существующий файл. |

Программа пишет диагностику в stderr. Даже если другой процесс создаст отчёт во время чтения логов, его файл сохранится.
